# 抽出ルール（mentions.jsonl の書き方）

課金を避けるため、記事を読んで商品を書き出す「抽出」はAPIではなく、プロジェクトのスレッド内でClaudeが行います。
パイプライン（`korekae run`）は、その結果である `data/<年>/sources.jsonl` と `data/<年>/mentions.jsonl` を入力にします。

## sources.jsonl（1行1ソース）

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| id | ○ | ソースID。`サイト名-年` のように人が読める形にする |
| url | ○ | 記事・動画のURL |
| kind |  | blog / note / hatena / scrapbox / media / youtube / x / other |
| title |  | タイトル |
| author |  | 著者。同じ著者の複数記事を1人と数えるのに使う。不明なら省略 |
| published_at |  | 公開日 YYYY-MM-DD |
| lang |  | 既定は ja |

## mentions.jsonl（1行1言及）

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| source_id | ○ | sources.jsonl の id |
| name | ○ | 商品名。「ブランド 商品名 型番」の形にそろえる（色・容量・セット数は省く） |
| brand |  | ブランド名 |
| amazon_url |  | 記事内の、**その商品そのもの**へのAmazonリンク（amzn.to も可） |
| asin |  | URLから取れないASINを手で補うとき |
| rank |  | 記事内で明示された順位（「1位」「ベスト1」など）。番号付きの見出しだけなら付けない |
| category |  | ガジェット / 家電 / 生活用品 / 食品 / ファッション / 本 / サービス / ゲーム / アプリ / その他 |
| comment |  | 短い要約。**記事本文は転載しない** |

## 作業の流れ

1. 検索・はてなブックマーク・noteのタグなどで記事URLを集め、`korekae candidates add` で候補に入れる（URLを正規化して重複を除く）。
2. 候補を20〜30件ずつ読み、次の形式で書き出す。
   ```
   SOURCE  {"id": ..., "url": ..., "title": ..., "author": ..., "published_at": ...}
   MENTION {"source_id": ..., "name": ..., "brand": ..., "amazon_url": ..., "rank": ..., "category": ...}
   SKIP    <ID または URL> <理由>
   ```
3. `korekae ingest` で取り込む。候補の状態（todo / extracted / skipped）も更新される。取得に失敗した記事は todo のまま残るので、次の回に読み直す。
4. note は同時に何件も取得するとレート制限がかかるため、1件ずつ順番に読む。

## 何を言及に含めるか

- 含める: 記事の本編で「買ってよかった」として紹介された商品。
- 含めない: ブランドも商品名も分からない一般名（「靴下」など）、音楽・映画・イベント、PR・広告枠、「こちらもおすすめ」「Amazonで人気の○○」などの別商品、「選外」「保留」、関連として触れただけの商品、商品名のない「その他」。
- Amazonリンクの商品名が記事の商品と違う（類似品・別モデル）ときは `amazon_url` を付けない。
- 同じ記事で複数の人がそれぞれ順位を付けている場合（編集部員ごとのベスト3など）は、各人の順位をそのまま rank に入れる。

## 2025年版の試運転（M1）で決めたこと

- 10記事（Scrapbox 3、メディア 6、ブログ 1）から83件の言及を書き出した。
- ライフハッカーの「編集部のベストバイ」は4人の編集者の記事だが、著者は1つ（編集部）として扱っている。
